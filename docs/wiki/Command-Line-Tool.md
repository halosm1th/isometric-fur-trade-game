# The command-line tool

Everything the [web editor](Web-Editor) does is also a command. Run them from inside the repository:

```
dotnet run --project tools/CampaignTool -- <command> [file] [options]
```

| Command | What it does |
|---|---|
| `check story.camp` | Compile and check. Errors fail (exit code 1); warnings do not unless `--strict`. `-v` adds the gentle notes. Also accepts a `.json` campaign. |
| `compile story.camp [-o story.json]` | Compile to the JSON the game reads (after checking it; `--force` writes even with errors). |
| `install story.camp` | Compile into `Campaigns/story.json`, where the game's menu lists it. |
| `build` | Compile every `tools/CampaignTool/src/*.camp` into `Campaigns/*.json`. Run it after editing a script in `src/`. |
| `decompile Campaigns/x.json [-o x.camp]` | The other way: write an old JSON campaign as a script. The script compiles back to exactly that JSON. |
| `graph story.camp` | The beats and what leads to what, as a mermaid flowchart (`--dot` for graphviz). |
| `sim story.camp --scenario s.json` | Play the campaign forward; see [Simulation scenarios](Simulation-Scenarios). |
| `serve [--port N]` | Start the [web editor](Web-Editor). |
| `docs [-o file]` | Write the [Library reference](Library-Reference) from the library table. |

Any command that takes a script also takes a `.json` campaign.

## Errors

A compile error names the file, line and column:

```
error: story.camp: line 77: world has no 'setLondn'. Did you mean 'setLondon'? It has tension, standing, ...
```

See [Troubleshooting](Troubleshooting) for what the common ones mean.

## Where things live

| Path | What |
|---|---|
| `tools/CampaignTool/src/*.camp` | The campaigns the repository ships, as scripts. Edit these. |
| `Campaigns/*.json` | What the game reads. Generated from `src` by `build`; a test fails if they disagree. A campaign here with no script (`Gemini and Clark.json`) is still valid: open it in the editor to get one. |
| `tools/CampaignTool/examples` | The small examples, and the simulator's example worlds (`*.scenario.json`). |
| `docs/wiki` | These pages. `Library-Reference.md` is generated by `docs`. |

## For the game's programmers

The tool compiles the same two files the game does (`Scripts/Core/CampaignLogic.cs` and `CampaignRunner.cs`: pure C#, no engine types), so a script behaves identically in the simulator and in the game. The language itself is in `tools/CampaignTool`:

| File | What |
|---|---|
| `Source.cs` | tokens, lexer, spans and diagnostics |
| `CampAst.cs`, `CampParser.cs` | the syntax tree and the recursive-descent parser |
| `Library.cs` | the typed table of everything the language provides; the compiler runs it, the editor completes from it, the wiki is written from it |
| `Compiler.cs` | the compiler: evaluates constants, functions and loops, and writes the JSON |
| `Decompiler.cs` | JSON back to script, verifying each piece compiles back to the same JSON |
| `Check.cs`, `Graph.cs`, `Sim.cs` | the checker, the graph, the simulator |
| `Server.cs`, `web/` | the web editor |

`dotnet test tests/CampaignTests` runs the whole suite, including *every shipped campaign decompiles and recompiles to identical JSON*.

To add a word to the language, add a row to `Library.cs` (with its description and an example: the tests insist) and run `docs`.
